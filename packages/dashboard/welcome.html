A lab test for your code's compliance.

In a lab, an assay tells you what is in a sample. Acai does the same for software. It reads a repository, works out which regulations and standards apply, and lists what is missing, with the file and line. A person signs off on every result.

What it's for

Knowing which rules apply, and whether your code meets them

Software that reaches real people has rules to follow: privacy laws, security and safety standards, app store policies. Working out which ones apply to your product, and where your code falls short, is slow and easy to get wrong. Acai does the first pass and keeps a person in charge of every decision.

It works out what you are building

A bounded scan of the code spots embedded C and RTOS, CAN and UDS, AUTOSAR, OTA updates, web servers, mobile manifests, LLM and ML libraries, and health, payment, children's or location data.

It asks before it assumes

Where you sell, to whom, what data you handle, how AI is used, the safety level. Drafted answers stay unconfirmed until a person confirms them, and a framework that depends on a missing answer shows as undecided rather than guessed.

It shows its evidence

Every finding points to a file and line, or to a document that should exist but doesn't, such as a TARA, a DPIA or an SBOM. It also names the clauses it relates to and says what to change.

How it works

The procedure

Like a lab protocol: the same steps every time, in order, and all of it written down.

  1. 1

    Understand

    Scan the repository and classify the product. With a model, the agent also reads the README and entry points.

  2. 2

    Ask

    Answer the questions that decide which rules apply, or start from a preset such as automotive-ecu-asil-b.

  3. 3

    Scope

    Each framework applies, doesn't apply, or waits for a missing fact. You can include or exclude any by hand.

  4. 4

    Audit

    Detectors report file and line; missing evidence becomes an evidence gap. With a model, the agent checks every in-scope control.

  5. 5

    Review

    You confirm, reject, modify or send back each finding for re-investigation.

  6. 6

    Fix and verify

    Fixes go to a branch, one commit per finding. Each must build, pass the tests and make the detector stop matching.

  7. 7

    Report

    Markdown, JSON or SARIF. Re-audit later: rejected findings stay rejected, fixed ones that come back are reopened.

Who it's for

From firmware to web apps

The rule registry is plain YAML: 48 frameworks with 798 controls. Each control has a paraphrased requirement, guidance on what to look for in code, and the evidence that shows it is met.

Tags in Findings: regulation standard guideline or policy

Embedded and automotive

Firmware, ECUs, IoT devices and industrial controllers.

Acai recognises C and C++, RTOS code, CAN and UDS, AUTOSAR, OTA updates, BLE and Wi-Fi. Its detectors flag unbounded string functions, dynamic allocation in firmware, missing watchdogs, unsigned firmware updates, unauthenticated CAN and weak UDS security access. It also reports evidence gaps such as a TARA, a safety case or an SBOM. Fixes are verified with your own make, CMake or other build.

Everyday software

Web apps, APIs, SaaS and mobile apps.

For products that handle personal data, payments or health information, Acai checks privacy, security and store rules. It looks for hard-coded secrets, personal data in logs, weak password hashing, injection risks, insecure cookies, missing security headers or rate limiting, and tracking SDKs. It also checks for documents such as a privacy notice, a cookie consent mechanism, a DPIA or records of processing.

Bring your own standards

On an on-premise server, an administrator can add new frameworks or update the built-in ones as YAML files, without rebuilding. That covers a newer ISO revision or your company's internal standard. Do it in the dashboard under Admin → Frameworks, or with acai frameworks add <file.yaml>.

Lab results

How to read a report

Here is a real example: a detector-only run on the open-source CANopenNode stack, with no model involved. Each finding says:

How serious
Critical, high, medium, low or info.
Where
The file and line, or the document that is missing.
Why
The clauses it maps to, tagged by framework.
What to do
A recommendation, ready to hand to you or to a coding agent.

Exports: Markdown, JSON or SARIF for code scanning.

You stay in charge

Agents can suggest. People decide.

For every finding you can confirm it, reject it with a reason, modify its severity or text, or send it back to be re-investigated with a note. No agent can make these decisions. The rule is built into the review state machine.

Fixes go to their own branch, acai/fixes-<audit>, one commit per finding. You approve the build and test commands first, because they run project code. A fix that fails is fed back for another attempt, and rolled back if it still fails. Then you accept the fix or revert it.

F-001Open

Unbounded C string function in CO_SDOclient.c

sprintf → snprintf(msg, sizeof msg, …)

An example of what a finding's history records.

  1. you confirmed it
  2. agent changed 1 file on acai/fixes-…
  3. ✓ build ✓ tests ✓ detector no longer matches
  4. acai committed it with an Acai-Finding trailer
  5. you accepted the fix

Ways to use it

Wherever you already work

Acai's own agents can run on Claude, GPT, Gemini, Mistral and other providers, or on a local model through Ollama or LM Studio. With no model at all, the 41 detectors and 30 evidence checks still run, and a connected coding agent can do the reasoning.

Dashboard

A review page for a team, covering many repositories: findings, fixes, scope, reports.

acai serve ./repo-a ./repo-b

Your coding agent

Claude Code, Codex, Copilot, Cursor and other MCP clients. Acai hands over findings as fix tasks, then builds, tests and commits each fix for you to accept. 

claude mcp add acai -- node /abs/path/dist/acai/acai.mjs mcp . --dashboard

Terminal

An interactive session from start to finish. --static runs detectors only.

acai audit ./repo

CI

Fails the build while unresolved findings at or above a threshold remain, and writes SARIF for code scanning.

acai ci . --fail-on high --sarif acai.sarif

Webhooks

On every push or pull request from GitHub, GitLab or any CI, Acai audits the change. With a token it reports back as a commit status and a pull request comment. 

https://<host>/hooks/github

VS Code

Findings in the Problems panel and a tree view, the dashboard in a panel, and MCP for Copilot agent mode.

npm run build:vscode

Here acai is short for node dist/acai/acai.mjs.

Start using Acai

Your first assay in three steps

You need Node.js 22.12 or later, and git.

  1. 1

    Build it

    npm ci && npm run build
  2. 2

    Point it at a repository

    node dist/acai/acai.mjs serve /path/to/repo
  3. 3

    Open the dashboard

    Go to http://127.0.0.1:4317, open the project and click Run detector audit. When you want Acai's agent to look deeper, add a model on the Model page.

On a server for your team, with Docker 
cp .env.example .env        # set ACAI_ADMIN_TOKEN=$(openssl rand -hex 32)
mkdir repos && git clone <repo> repos/<name>
docker compose up -d --build

Sign in with ACAI_ADMIN_TOKEN, then add people under Admin. TLS, backups, Kubernetes and air-gapped installs with a local model are covered in docs/DEPLOY.md.

Good to know

What Acai is, and what it isn't

Not legal advice

Acai helps you find gaps and gather evidence. It does not certify anything. Licensed standards (ISO, IEC, SAE, MISRA, PCI) are paraphrased with clause references, never copied. Check anything you rely on with counsel.

Your code stays with you

There is no SaaS and no database: state is plain JSON in <repo>/.acai/. Only agent features send file excerpts to the model you chose, with secrets redacted. .env and key files are never sent.

A trail you can check

Every decision goes into a hash-chained journal, and acai journal --verify checks the chain. You can commit .acai/ as your audit record.

Dates and versions

Framework dates and versions were checked against official sources in October 2026 where possible. Each framework's notes say what was verified.
